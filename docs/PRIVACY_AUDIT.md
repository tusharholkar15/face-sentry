# FaceSentry Privacy Audit

## Executive Summary
FaceSentry is designed with a strict **Local-Only Privacy Model**. 
No data is ever transmitted to the internet. All processing, modeling, and storage occurs on the local Windows hardware.

## 1. Data Collection & Processing

### 1.1 Live Camera Feed
- **Behavior:** The agent captures frames from the default webcam.
- **Privacy Enforcement:** Video frames exist exclusively in memory for milliseconds to pass through the YuNet face detector and SFace recognizer. They are **never** written to disk. The agent does not record video.

### 1.2 Biometric Extraction
- **Behavior:** SFace extracts a 128-dimensional array of floats representing a face (the embedding vector).
- **Privacy Enforcement:** The mathematical embedding cannot be reliably reverse-engineered into a photograph of the user's face. 

### 1.3 Enrollment Images
- **Behavior:** During the setup wizard, 10 frames of the user's face are aggregated.
- **Privacy Enforcement:** Once the centroid embedding is calculated, the raw images are immediately discarded from memory. No "Enrollment Database" of photos is kept.

## 2. Data Storage Locations

All persistent data generated by FaceSentry is stored in the current Windows user profile under `%LOCALAPPDATA%\FaceSentry`.

| Data Type | Content | Storage Location | Protection Mechanism |
| :--- | :--- | :--- | :--- |
| **Biometric Profile** | Serialized 128-d embedding | `enrollment\profile.enc` | **Windows DPAPI** (Encrypted using the logged-in user's cryptographic context. Cannot be decrypted by other users or if copied to another machine). |
| **PIN Hash** | Argon2id Hash | `facesentry.db` | Salted, irreversible hashing. |
| **Configuration** | Timeouts, Thresholds, Toggles | `facesentry.db` | Plaintext SQLite. |
| **Telemetry Events** | Auth state transitions, lock events | `facesentry.db` | Plaintext SQLite. Explicitly stripped of biometric vectors before logging. |

## 3. Uninstallation and Data Destruction
The uninstallation process (`scripts\uninstall_windows.ps1`) explicitly asks the user for authorization before destroying the `%LOCALAPPDATA%\FaceSentry` folder. 
Because the biometric profile is tightly coupled to DPAPI, if the Windows user account is deleted or password reset forcefully by an admin, the `profile.enc` file becomes cryptographically unrecoverable by design.

## 4. Conclusion
FaceSentry meets strong privacy requirements. It achieves "zero external data exposure" and implements minimal local storage by exclusively retaining encrypted mathematical representations rather than highly sensitive imagery.
